Executive summary

How a validated submission will be made

NOT READY — DO NOT SUBMIT

There is currently no downloadable submission TIFF. The JSON run card is a negative research result, not a file accepted by the competition. Do not submit the mirrored template, labels, fault mask or a source-code document.

What the project must do automatically first

  1. Reuse canonical cached features, evaluator and writer, within the assigned method lane. Derive catalogue features solely from visible faults in each fold.
  2. Withhold whole fault segments with a buffer; mask visible faults pixel-exactly. Test individual features for leakage. Use pooled distance-tolerant Tversky with the specified triangular kernel.
  3. Report HOLDOUT-DTI with evaluator version, withheld positives and a block/segment-based confidence interval. Compare against a contemporaneous incumbent on the identical folds. Do not use a calibrated projection as a score.
  4. Reject a duplicate surface or dot set against the full registry. Do not rely on a new filename as evidence of novelty.
  5. Write a single-band GeoTIFF using the shared submission writer. Re-open it and verify exact CRS, shape and transform against the authenticated competition template, finite footprint coverage and values in [0,1]. Retain the exact file SHA-256.
  6. Publish an explicit readiness result and a direct TIFF download with a unique name and note of at most 140 characters. These remain absent until a candidate exists and passes.

Contest upload — only after separate selection

  1. Confirm rules and current weekly quota on the authenticated competition page. This project cannot verify your account's quota.
  2. Download the explicitly approved TIFF and verify its SHA-256 against the published run card.
  3. On the competition's New submission form, choose that TIFF (or a ZIP containing that one TIFF) and paste its published short note. This format description is from the user-supplied form text; the live form was not accessible here.
  4. Keep the actual submission-page receipt. Only a receipt-backed result may be labeled ORGANIZER-CONFIRMED. Do not report this project's holdout as the organizer score.

Why the earlier range error matters

Negative nodata sentinels, values over one, infinity or NaN can invalidate predictions. A GeoTIFF nodata declaration does not prove the submission service ignores those pixels. Our independent format auditor inspects raw values across the whole raster and rejects, rather than clips, invalid candidates. It never grants scientific or quota approval.

python scripts/validate_artifact.py candidate.tif data/sample_submission.tif --output evidence/candidate-format.json

The local mirrored template's integrity is verified against an upstream hash, not authenticated by DrivenData. A successful audit against it would still be format-only.

Limitations and next step

There is no model or required shared template in this repository, no holdout incumbent, and no complete registry. The specific method paragraph is missing. These prevent an honest unique, validated TIFF. No manual raster inspection is requested to bypass the blockers.
